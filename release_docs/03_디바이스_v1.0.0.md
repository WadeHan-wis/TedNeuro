# fNIRS 디바이스 명세 v1.0.0

| 항목 | 내용 |
|---|---|
| 대상 | fNIRS PoC v1 보드 + 펌웨어 v1.0.0 (2026-10-08, BLE 이름 `TedNeuro_v1.0.0`) |
| 대상 독자 | 앱·분석·검증 담당, 하드웨어 담당 |
| 함께 보는 문서 | `01_프로토콜_v1.0.0.md`(BLE 인터페이스), `02_파라미터_v1.0.0.md`(값), `pinmap.md`(핀 상세) |
| 상태 | 회로도(스키매틱) 기준 정리. **실물 보드와의 리비전 차이는 실측으로 재확인이 필요하다** |

## 한눈에 보기
- **nRF52832 + AS7341 2개 + LED 3개(640/680/980nm)** 로 이마에서 근적외선 raw 신호를 BLE로 보내는 장치다. 기기는 raw만 보내고 분석·보정은 하지 않는다.
- 전원 스위치를 켜면 자동으로 광고를 시작하고, 앱이 접속해 CONFIG를 써 주면 측정을 시작한다.
- **착용 감지, 배터리·충전 상태 읽기, 온보드 저장은 없다.**
- 센서 초기화에 실패하면 그 센서만 빼고 계속 동작하며 raw는 0으로 나간다(알려진 제약).
- 이 문서는 "기기가 어떻게 동작하는가"를 설명한다. 값은 `02`, 전송 형식은 `01`을 본다.

## 1. 하드웨어 구성

| 구성 | 부품 | 비고 |
|---|---|---|
| MCU / BLE | nRF52832-QFAA-R (U1) | Cortex-M4, BLE 5, 칩 안테나 |
| 센서 | AS7341 × 2 (NIR1=U8, NIR2=U9) | **센서마다 독립 I2C 버스**, 한쪽 고장이 다른 쪽에 영향 없음 |
| LED | 640nm (D2) / 680nm (D3) / 980nm (D4, 스펙 950nm) | PWM으로 밝기 조절, 3개 동시 점등 |
| 저속 클럭 | 32.768kHz 크리스탈 (LFXO) | 100ms 샘플링 기준 |
| 전원 | 무선충전 수신(BQ51050B), 전원 스위치(MAX16054), 1.8V/3.3V LDO | 아래 §4 참고 |
| 디버그 | SWD 2핀 헤더(P1: SWDCLK/SWDIO) | VDD/GND는 별도 확인 필요 |

- LED3는 스펙이 950nm이나 PoC v1에는 980nm 부품이 실장돼 있다. 다음 PCB 리비전에서 950nm로 교체할 예정이다.
- AS7341의 INT/GPIO 핀은 MCU에 연결돼 있지 않다. 그래서 **데이터 준비 인터럽트 없이 100ms tick 기준으로 읽는 구조**다.
- NFC 핀(P0.09/P0.10)은 센서 1의 I2C로 쓰기 위해 GPIO로 전환했다. NFC는 쓸 수 없다.

### 1.1 핀 배치 (요약, 상세는 `pinmap.md`)

| 기능 | MCU 핀 |
|---|---|
| LED1 640nm 제어 | P0.04 |
| LED2 680nm 제어 | P0.05 |
| LED3 980nm 제어 | P0.06 |
| 센서 1 (NIR1) I2C | SCL P0.09 / SDA P0.10 |
| 센서 2 (NIR2) I2C | SCL P0.08 / SDA P0.07 |
| SWD | SWDCLK / SWDIO 헤더 P1, nRESET P0.21 |

- I2C 풀업은 4.7kΩ(1.8V). 센서 1은 R3/R4, 센서 2는 R1/R2다.

## 2. 동작 흐름

```
전원 ON → 부팅 → 광고 → (앱 접속) → CONFIG 쓰기 → 측정·전송
                              ↑                 │
                              └─ 재접속 ←── 연결 끊김 ──22초 초과──→ STANDBY(측정 중단, 광고 유지)
```

| 단계 | 기기 동작 | LED 표시 |
|---|---|---|
| 전원 ON·부팅 | 센서 2개 초기화, BLE 시작, 광고 시작. 부팅 도달 확인용으로 LED1·2를 점등 | LED 3개가 함께 **3회 점멸**(150ms) |
| 광고 중(미접속) | 접속 대기. 측정은 시작하지 않음 | LED 1개씩 **1초 간격으로 순차 점등** (밝기 20%) |
| 앱 접속 | 연결 파라미터 협상, MTU 247 | LED **10회 점멸**(약 2초) |
| 측정 중 | CONFIG대로 LED 점등·센서 적분, 샘플을 2초마다 묶어 전송 | CONFIG의 주기·듀티로 점등 |
| 연결 끊김 (22초 이내) | **측정·버퍼링 계속**(220샘플), 광고 재시작 | 측정 중과 같음 |
| 22초 넘게 미접속 | **STANDBY**: 측정 중단(발열·전력 절감), 광고는 계속 | LED1만 2초마다 100ms 점멸 |
| STANDBY에서 재접속 | 10회 점멸 후 측정 재개 (CONFIG는 앱이 다시 써야 함) | 10회 점멸 |

- 전원 스위치(SW1)는 하드웨어로 전원을 끊고 켠다. MCU가 읽을 수 있는 핀이 아니라서 "소프트웨어 전원 OFF"는 없다.
- 광고 이름은 `TedNeuro_v{버전}`이며 펌웨어 업데이트 후 바뀐다. 현재 버전은 `AS7341_VERSION(0x1528)`으로도 읽을 수 있다.
- 부팅 점멸 횟수는 버전과 무관하게 3회로 고정이다(패치 버전만큼 점멸하던 방식은 워치독과 충돌해 v0.1.21에서 바꿨다).

## 3. 소프트웨어 구조

| 태스크 | 우선순위 | 역할 |
|---|---|---|
| 측정 (`m_i2c`) | 2 (가장 높음) | 100ms tick마다 LED 구동, AS7341 읽기, 링버퍼 저장 |
| BLE (`m_ble`) | 4 | 묶음 전송, CONFIG 처리, 접속·광고 관리 |
| 제어 (`m_ctrl`) | 6 | 상태 관리, 오류 처리, 워치독, 리셋 |

- 숫자가 작을수록 우선순위가 높다. 측정이 BLE 때문에 밀리지 않도록 정한 순서다.
- 100ms tick은 하드웨어 RTC 인터럽트에서 만든다. 인터럽트 안에서는 시각 기록과 신호 전달만 하고 I2C·BLE·로그는 하지 않는다.
- **시스템 리셋은 제어 태스크만 한다.** 다른 모듈이 직접 리셋하지 않는다.
- 각 태스크는 자기 초기화를 스스로 수행한다. `main()`은 부팅 로그를 남기고 대기한다.

## 4. 전원·배터리

- 전원 회로 구성: 무선충전 수신(BQ51050B), 이상적 다이오드 컨트롤러(LTC4412), 전원 스위치 컨트롤러(MAX16054), 1.8V·3.3V LDO. LED 전원은 3.3V다.
- MCU 내장 DC/DC(벅 컨버터)를 켰다(전류 절감 목적). 파워서플라이 실측에서는 켜고 끈 차이를 구분하지 못했다(측정 해상도 한계).
- **MCU는 충전 상태와 배터리 잔량을 읽을 수 없다.** 현재 회로도에 그런 배선이 없다(실제 배선 여부는 하드웨어 담당 확인 필요). 배터리·온도 감시와 열 보호는 v1.0에 포함되지 않았다.
- **전류 (0dBm 기준 실측, -8dBm 값은 미측정):** 광고 중 약 5mA, 측정 중 약 28mA.
- 배터리 용량과 12시간 사용 시간은 아직 확정·검증되지 않았다(`02_파라미터_v1.0.0.md` §6).

## 5. 신뢰성 동작

| 상황 | 기기 동작 |
|---|---|
| 측정·BLE 태스크 중 하나가 멈춤 | 워치독(4초)이 리셋. 재부팅 후 리셋 원인을 로그에 기록 |
| 센서 읽기 실패 | 센서 재초기화를 최대 3회 시도(I2C 버스 복구 포함) |
| 재초기화로도 안 됨 | 소프트웨어 재부팅 최대 3회. 그 뒤에도 재발하면 재부팅을 멈추고 **영구 안전 상태**(전원을 껐다 켜야 해제) |
| 부팅 때 센서 초기화 실패 | 그 센서만 배제하고 계속 동작. 배제된 센서 raw = 0, 재부팅 전까지 복구 안 됨 |
| 연결 끊김 | §2 참고. 22초 동안 측정·버퍼 유지 |
| 포화(과다 입사광) | AS7341 상태 비트로 기기 내부에서 판정하지만 **패킷에는 실리지 않는다**(상태 필드 없음) |

- 배제된 센서와 정상 0값은 앱에서 값만 보고는 구별되지 않는다. 계속 0이면 센서 사용 불가로 본다.
- 재부팅 에스컬레이션의 의료기기 단일 고장 안전 정합성은 정식 심사 전이다.

## 6. 펌웨어 업데이트

- 무선(OTA)으로 업데이트한다: MCUboot + SMP, Test → 확인 → Confirm. 상세는 `01_프로토콜_v1.0.0.md` §7.
- 최초 공급(공장 프로그래밍)은 유선(SWD)으로 `mcuboot.hex`와 앱 hex를 순서대로 쓴다. 절차는 `RELEASE_NOTES_v1.0.0.md` §2.
- 업데이트 서비스에 인증이 없고(서명키는 디버그 키, 페어링 없음) 양산 전 결정이 필요하다.

## 7. 메모리·리소스

| 항목 | 사용량 (v1.0.0) |
|---|---|
| 앱 Flash | 162,672B (75.05%) |
| RAM | 60,624B (92.50%) |
| MCUboot Flash | 70.74% |

- RAM 여유가 약 7.5%뿐이다. 링버퍼(220샘플), 로그 버퍼, OTA 버퍼가 큰 비중을 차지해 **링버퍼 확장이나 기능 추가가 어렵다**(300샘플로 늘리면 약 96%).

## 8. 알려진 제약과 미구현

| 구분 | 내용 |
|---|---|
| 하드웨어 | LED3가 980nm(스펙 950nm). 센서 2(U9)는 일부 시제품에서 납땜 접촉 불량 의심 |
| 센서 상태 | 초기화 실패·포화·I2C 오류가 패킷에 표시되지 않음 (v1.x) |
| 착용 | 기기가 착용 여부를 모름. 이탈 구간은 앱·분석에서 제외 |
| 시계 | 폰 대비 약 +107ppm 빠름, 절대시각 없음 |
| 저장 | 온보드 저장 없음. 22초 넘게 끊기면 해당 구간 기록 안 됨 |
| 보안 | 페어링·암호화 없음, OTA 서명키가 디버그 키 |
| 전원 | 배터리 잔량·충전 상태·온도 감시 없음 |
| 인터페이스 | `location_interval`, `led4_pwm`은 CONFIG 필드가 있으나 효과 없음 |
| 기타 | 적분시간이 정확히 100ms가 아닌 99.8ms |
