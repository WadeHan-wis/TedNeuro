## 한눈에 보기
- 측정 핵심값: **LED 25/50/75%(640/680/980nm 동시 점등), Cycle 300ms / Active 100ms, 게인 256x, 적분시간 약 99.8ms, dark 3:1.**
- 이 중 **적분시간과 Cycle/Active는 앱이 접속할 때마다 CONFIG로 써야 적용된다.** 펌웨어 기본값(적분시간 약 19.7ms, 100/100ms)은 검증된 측정 설정이 아니다.
  - CONFIG 페이로드: `05 01 19 32 4B 00 2C 01 64 00`
- 값을 누가 정하는지는 §1의 "설정 경로"로 구분한다: **앱 CONFIG** / **펌웨어 고정**.
- 장시간·배터리·도달 거리 값은 일부가 **0dBm 기준**이다(§6 표 참고). 착용 상태 측정과 12시간 연속 수면은 아직 없다.

## 1. 측정 파라미터

| 항목 | 값 | 설정 경로 | 비고 |
|---|---|---|---|
| LED 파장 | 640nm / 680nm / 980nm | 하드웨어 | 3번째 LED는 스펙 950nm이나 PoC v1은 980nm 부품 실장 |
| LED PWM duty | 25% / 50% / 75% | 앱 CONFIG(펌웨어 기본값도 같음) | 공동연구 자료 기본값과 같은 조합 |
| PWM 주기 | 1ms (1kHz) | 펌웨어 고정 | |
| LED 점등 방식 | 3파장 **동시** 점등 | 펌웨어 고정 | 시분할 아님 |
| Cycle / Active | 300ms / 100ms | **앱 CONFIG 필수** | 기본값은 100/100ms(게이팅 없음, 약 10Hz) |
| 게인 | AGAIN=9 (256x), 6채널 공통 하나의 게인 | 펌웨어 고정 | 런타임 변경 없음(채널별 게인 아님) |
| 적분시간 | ATIME=99, ASTEP=358 → **약 99.80ms** | **앱 CONFIG 필수** (`integration_time`=5) | 기본값은 1단위 → 약 19.7ms. 정확히 100ms가 아님 |
| dark 프레임 | lit 3개당 1개 (**3:1**), LED 전부 OFF, 게인·적분시간 동일 | 펌웨어 고정 | v0.1.34부터 3:1 (그 전에는 10:1) |

CONFIG 필드별 범위는 `01_프로토콜_v1.0.0.md` §2에 있다. 이 문서는 "어떤 값으로 쓸지"만 정한다.

### 1.1 전원 인가 기본값 vs 앱이 쓰는 값

| 항목 | 전원 인가 기본값 | 앱이 쓰는 값 (필수) |
|---|---|---|
| 적분시간 | 약 19.7ms | 약 99.8ms |
| Cycle / Active | 100ms / 100ms (게이팅 없음) | 300ms / 100ms |
| LED duty | 25 / 50 / 75% | 25 / 50 / 75% |
| 게인 | 256x | 256x (CONFIG에 없음) |
| dark 비율 | 3:1 | 3:1 (CONFIG에 없음) |

- 기본값은 재부팅·전원 사이클마다 돌아온다. 접속·재접속 때 CONFIG를 다시 쓴다.

## 2. 샘플링 타이밍

| 항목 | 값 |
|---|---|
| lit 샘플 간격 | 300ms (센서당 약 3.33Hz). dark가 끼어도 lit-lit 300ms 유지 |
| dark 위치 | 직전 lit 100ms 뒤에 dark, 그 200ms 뒤에 다음 lit |
| 기준 tick | 100ms (32.768kHz LFXO, 5프레임 주기로 3277×4+3276 = 16384 tick = 정확히 500ms) |
| `timestamp_us` | u32, 71.58분마다 0으로 되돌아감(앱이 unwrap). 기기에 절대시각 없음 |
| tick 어긋남 | 약 1분에 한 번꼴로 0.2초/0.4초 쌍이 생길 수 있음. 평균 간격 0.300초, 유실 없음 |
| 기기 시계 오차 | 폰 시계 대비 약 **+107ppm** (12시간에 약 4.4초). 샘플링 간격(300ms)에는 영향 없음 |

- 시계 오차는 6개 세션(기기 3대, 앱 2종)에서 +101~112ppm으로 일정했다. 원인은 확정하지 못했다(§7).

## 4. 안정성 파라미터

| 항목 | 값 | 동작 |
|---|---|---|
| Watchdog | 4초 | 측정 태스크와 BLE 태스크가 둘 다 살아 있어야 feed. 한쪽이 1초 넘게 응답이 없으면 feed 중단 → 4초 뒤 리셋 |
| I2C 오류 복구 | 최대 3회 재초기화 | 센서를 다시 초기화(WHOAMI+SMUX, 버스 복구 포함). 연속 실패가 3회에 이르면 오류로 보고 |
| 오류 재부팅 | 최대 3회 | 보고된 오류가 재발하면 소프트웨어 재부팅 3회까지 시도. 그 뒤에도 재발하면 더 이상 재부팅하지 않고 **영구 안전 상태**로 전환 |
| 재부팅 횟수 초기화 | **전원을 물리적으로 껐다 켜야 함** | 세션 중 복구돼도 횟수는 되돌아가지 않는다 |
| 센서 초기화 실패 | 해당 센서만 배제하고 계속 | 배제된 센서의 raw는 0으로 전송, 재부팅 전까지 복구 안 됨 |

- 재부팅 에스컬레이션이 의료기기 단일 고장 안전 요구와 정합한지는 정식 심사를 받지 않았다(§7).

## 7. 미확정·미검증

**미검증 (아직 측정하지 않음)**
- **착용 상태 측정(v1.0.0)** — 연휴 중 진행 예정.
- **12시간 연속 수면** — 최장 4.6시간.
- **같은 조건 3일 이상 반복** — 현재 같은 기기 2일.
- **-8dBm 기준 배터리·도달 거리** — 값은 0dBm 기준만 있음.
- **여러 대 OTA** — 1대에서만 확인.

**미확정 (원인·결정 대기)**
- 아래 센서 초기화 실패와 D7 샘플 간격 혼재는 **고장 PCB가 대상이어서 v1.0 범위에서는 보류**로 정리했다.
- **기기 시계 +107ppm:** 소프트웨어 원인은 배제했다(합계 16384 tick, `K32SRC=XTAL`). 후보는 LFXO 부하 용량 부족과 폰 시계이며 아직 가려내지 못했다. 가르려면 같은 기기를 폰 2대로 동시 기록하거나 주파수 카운터로 측정한다.
- **센서 초기화 실패(하드웨어 의심):** 센서 2(U9) 납땜 접촉 불량이 유력하다(열풍기 재납땜 2대, 센서 교체 1대 정상화, 원인 확정 아님). 9A 센서 1은 2026-10-07에 `WHOAMI timeout`이 났으나 10-08 부팅 2회에서는 정상이었다(원인 미확인, 일시적일 가능성).
- **D7 방전 파일 샘플 간격 0.2/0.3/0.4초 혼재:** 원인 미확인.
- **오류 재부팅 에스컬레이션:** 선행 인증 기기(TedreamS2)의 같은 철학을 재사용했다. 정식 인증 심사에서는 논리적 동일성을 다시 확인해야 한다.

**v1.x로 넘긴 것**
- 적분시간 100.08ms 정밀화(현재 99.80ms, 레퍼런스와의 비교 조건이 0.28% 달라지고 야간 재측정이 필요해 보류)
- 패킷 상태 정보(포화·I2C 오류·센서 배제 표시), 오류 누적 카운터 특성
- flash 로컬 저장(앱 슬롯 여유가 약 54KB라 약 14분 분량, OTA 파티션 변경이 필요)
- 센서 재프로브(재부팅 없이 복구)
- 페어링·암호화, OTA 서명키 교체
- 3번째 LED를 950nm 부품으로 교체(다음 PCB 리비전)
